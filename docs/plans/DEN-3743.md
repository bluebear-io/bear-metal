# DEN-3743 — Document what bear-metal does

## Goal

Add a short, factual document that explains what bear-metal is and how it works at runtime: picking up delegated Linear tickets, implementing them, and opening PRs. No behavior changes.

## Changes

Docs only, in this repo:

- `docs/how-it-works.md` (new) — covers:
  - the scheduler loop (poll cadence, reconcile, decide, dispatch, concurrency);
  - Linear delegation versus assignment, and parking when delegation is removed;
  - a worker run: `customizeTask`, `buildWorkspace`, coding agent, PR open/update, task limits, heartbeats and reclaims, and per-ticket `maxIterations`;
  - reactions to PR signals: merge/close, review comments, failing checks (`shouldRetryCi`), merge conflicts, and human commits;
  - when bear-metal hands a ticket back and when it sends Slack notifications;
  - optional Slack thread coordination;
  - what bear-metal is not.
- `README.md` — link to the new document above the table of contents.

Every statement comes from current `main` (`src/manager/scheduler.ts`, `src/manager/config.ts`, `src/customization/types.ts`, and the README). Links point at existing README anchors. `#custom-runtime-image` replaces the removed `#worker-environment-builder` anchor, as DEN-4168 requires.
