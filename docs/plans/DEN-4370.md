# DEN-4370 — Show token-to-USD cost per Bear Metal task

## Findings

1. **Where token usage is available.** Every Bear Metal run is a Pi
   `AgentSession`. `session.getSessionStats()` returns token totals
   (`input`, `output`, `cacheRead`, `cacheWrite`) and `cost`: the USD sum of
   `usage.cost.total` across assistant messages. Pi computes each message's cost
   with `calculateCost(model, usage)` from the model registry's per-million-token
   rates (input, output, cache read, cache write, tiered rates, Anthropic 1h
   cache-write multiplier). Coding runs (`src/worker/pi.ts`) already read the
   token totals into `DispatchUsage`. Coordinator/research runs
   (`src/worker/slack-agent.ts`) already read them through `setAgentRunUsage`.
   Neither path keeps `cost`.
2. **Where to calculate costs.** Use Pi's per-message cost. It is the only
   place that knows the per-message token split and tier/cache pricing. A
   second Bear Metal price table would drift from Pi's registry. Persist it
   per run (task row) as `cost_usd`, next to `prompt_tokens` /
   `completion_tokens`.
   A model whose registry entry has zero input and output rates has no known
   pricing. Bear Metal stores `NULL` for it and logs a warning instead of
   recording a misleading `$0`.
3. **Where to surface it.** The dashboard task views:
   - Runs table (coding ticket detail and agent-run detail): new `Cost` column.
   - Coding ticket summary: `Cost` field with the sum of priced runs. If some
     runs used tokens but have no price, it shows a "N unpriced runs" note.
   - Agent-run (coordinator / research) summary: `Cost` field.

Slack notifications and Linear comments are out of scope; the ticket lists them
only as examples.

## Changes

- `src/db/schema.sql`: `cost_usd DOUBLE PRECISION` on `tasks` (create + idempotent
  `ALTER`).
- `src/worker/cost.ts`: `sessionCostUsd(model, stats)`. Returns Pi's session cost,
  `null` when the model has no pricing, and throws on a non-finite cost.
- `src/worker/types.ts`, `src/worker/pi.ts`: `DispatchUsage.costUsd`.
- `src/worker/slack-agent.ts`: pass cost to `setAgentRunUsage`. Like the coding
  path in `pi.ts`, a `sessionCostUsd` error is logged as a warning and the run is
  stored without cost; a cost-reporting error never fails a finished run.
- `src/db/client.ts`: `TaskRow.cost_usd`, `RunUsage.costUsd`,
  `AgentRunSummary.costUsd`, `RunWithUsage.costUsd`; write it in
  `upsertRunSucceeded` and `setAgentRunUsage`. When `upsertRunSucceeded` gets
  usage, its `costUsd` (including `null` for unpriced) replaces the stored cost;
  only a missing usage object keeps the previous value.
- `src/shared/dashboard/types.ts`, `src/ui/src/api/types.ts`: `costUsd` on run
  payloads.
- UI: `lib/format.ts` (`formatRunsCost`, built on the existing `formatCostUsd`),
  `TaskDetailSections.tsx` (Cost column), `CodingTaskDetail.tsx` and
  `TaskDetailPage.tsx` (Cost summary field).
- README: one sentence about per-run cost on the Tasks dashboard.

## Verification

- DB regression tests (`src/db/run-cost.test.ts`): `upsertRunSucceeded` and
  `setAgentRunUsage` persist `costUsd` and return it from `getTicketDetail` and
  `getAgentRunDetail`. A later succeeded write with an unpriced usage clears a
  previously stored cost to `NULL`.
- Worker unit test (`src/worker/cost.test.ts`): uses the real Pi model registry.
  A priced model returns the session cost, a zero-rate model returns `null`, and
  a non-finite cost throws.
- UI tests (`CodingTaskDetail.test.tsx`, `App.test.tsx`): the cost column and
  summary total render, and unpriced runs are counted.
- `npm run build`, `npm test`, UI tests/typecheck.
