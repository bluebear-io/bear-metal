# DEN-4166: Fix Bear Metal Scorecard workflow failing on main

## Problem

The main-branch OpenSSF Scorecard workflow ([2026-09-26 run](https://github.com/bluebear-io/bear-metal/actions/runs/36226038160/job/108360153386))
fails before analysis starts. The pinned `ossf/scorecard-action@v2.3.1` pulls
`gcr.io/openssf/scorecard-action:v2.3.1`, which now returns a
"billing-required" error from GCR.

Starting with v2.4.1, the action publishes its container to
`ghcr.io/ossf/scorecard-action`, so bumping past that version routes the pull
to GHCR and avoids the GCR billing error. Baloo Bear's [successful run](https://github.com/bluebear-io/baloo-bear/actions/runs/35871888840)
already runs v2.4.4 from GHCR.

Dependabot PR #129 bumps to v2.4.3; this PR supersedes it by going directly to v2.4.4.

## Changes

- `.github/workflows/scorecard.yml`: replace the SHA-pinned
  `ossf/scorecard-action@0864cf1...` (v2.3.1) with
  `ossf/scorecard-action@2d1146689b8cda280b9bc96326124645441f03bc` (v2.4.4),
  keeping the workflow's SHA-pinning convention and the trailing
  `# v2.4.4` version comment.

No other steps change. Permissions, triggers (`push` to `main`, `schedule`,
`branch_protection_rule`), and the SARIF upload step stay as-is.
