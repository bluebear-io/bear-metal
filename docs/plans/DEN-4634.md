# DEN-4634 — Report Pi session start and end to BlueBear

## Goal

BlueBear's Pi extension (`~/.pi/agent/extensions/bluebear.ts`) must see `session_start` and
`session_shutdown` for every Pi session Bear Metal runs: the coding worker and the Slack agent.

Verified against Pi 1.0.3:

- `AgentSession.bindExtensions()` emits `session_start`. The coding worker already calls it (DEN-4630);
  the Slack agent does not.
- `AgentSessionRuntime.dispose()` emits `session_shutdown` and then disposes the session.
  `AgentSession.dispose()` does not emit it, and both harnesses call `session.dispose()`.

## Changes

- `src/worker/pi-runtime.ts` (new): `createPiSessionRuntime()` builds an `AgentSessionRuntime` with
  `createAgentSessionRuntime()`, the default `agentDir` (`getAgentDir()`) and resource loader, an
  in-memory session manager, and the caller's model runtime, model, and tools.
- `src/worker/pi.ts`: create the session through `createPiSessionRuntime()`, keep the existing
  `bindExtensions` call on `runtime.session`, and end with `await runtime.dispose()`.
- `src/worker/slack-agent.ts`: create the session through `createPiSessionRuntime()`, call
  `await session.bindExtensions({ onError })` (logging extension errors) before prompting, and end with
  `await runtime.dispose()`.

## Verification

- `src/worker/pi-extensions.test.ts`: runs the worker through the real Pi runtime with an inline extension
  and asserts the order `session_start`, prompt, `session_shutdown` (reason `quit`), session dispose.
- `src/worker/slack-agent-deferral.test.ts`: asserts the Slack agent calls `bindExtensions` before the
  prompt and ends with `runtime.dispose()`.
- `npm run typecheck` and `npm test`.
